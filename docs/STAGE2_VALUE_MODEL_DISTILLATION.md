This workflow trains the stitching adapter and reward-encoder suffix to match a
frozen reward teacher, while the VAE and diffusion backbone remain frozen.
It starts from a locally fitted adapter and exports raw and EMA weights.

**The training recipe in this repository differs from the paper.**
Multi-resolution training was introduced to improve support across image
resolutions. The current recipe uses the buckets documented below and in
[shared setup](SETUP.md#multi-resolution-inputs-and-preprocessing); it is not an
exact reproduction of the paper's training setup or reported results. The stage
number is a repository workflow label.

Pretrained EMA checkpoints of the twelve pairs are
[published](../README.md#pretrained-checkpoints); the files described under
[outputs](#checkpoints-and-logging) are generated by your own training run.

## Setup

1. Complete [shared setup](SETUP.md), including both HPDv2 and AVA.
2. Run the matching [Stage 1 — Stitching-layer search](STAGE1_STITCHING_LAYER_SEARCH.md) recipe
   to create the initialization files under `$INIT`.
3. Match the adapter file to the layer pair in the [recipe table](#model-pair-defaults).
   If changing the pair, update the location and initialization path together.
4. For Aesthetic, also download the scoring MLP:

```bash
python scripts/download_weights.py aesthetic
```

## How to run

List the recipes and preview resolved commands before starting training:

```bash
bash scripts/stage2_train_stitched_model.sh
DRY_RUN=1 bash scripts/stage2_train_stitched_model.sh stage2_clip stage2_flux_dfn_clip
```

`DRY_RUN=1` prints the learning rate, effective batch settings, and full command
without loading data/models or training. It does not check initialization files
or available GPU memory. Run one or more recipes sequentially:

```bash
bash scripts/stage2_train_stitched_model.sh stage2_clip
# Examples for four GPUs; run only the model pairs you need.
NPROC=4 bash scripts/stage2_train_stitched_model.sh stage2_large_dfn_clip
NPROC=4 MICRO_BATCH_SIZE=2 bash scripts/stage2_train_stitched_model.sh stage2_clip
```

Use a fresh `OUT` root for a new run of the same pair. An existing model output
directory is refused; exact optimizer-state resume is not implemented.
Use the named shell recipes, because generic Python CLI defaults do not select
these complete configurations.

## Multi-resolution training and data

All pairs use HPDv2 + AVA with uniformly sampled VAE resolution buckets:

| Heads | VAE inputs (width × height) | Reward inputs |
|---|---|---|
| HPSv2 / CLIP / Aesthetic | 512², 768², 1024², 768×1024, 1024×768 | Native square input of each encoder |
| DFN-CLIP | 512², 768², 1024² | 378² |

The search and training buckets match. Distillation adds random resize/crop
and color jitter, with the same processed content in VAE and teacher views.
See [preprocessing details](SETUP.md#multi-resolution-inputs-and-preprocessing).
The current training recipe also uses EMA over trainable parameters.

## Shared training configuration

The executable settings live in
[scripts/stage2_config.sh](../scripts/stage2_config.sh) and the model-pair
[launcher](../scripts/stage2_train_stitched_model.sh).

| Setting | Value |
|---|---|
| Training length | Five epochs over the available concatenated training set |
| Initialization | Locally fitted affine adapter at the matching layer pair |
| Adapter | `F(x) + G(F(x))`; G = SiLU → 1×1 conv → SiLU → 1×1 conv |
| Residual width / initialization | Encoder hidden width / 8; last projection and bias initialized to zero |
| Trainable parameters | Affine adapter, residual branch, reward suffix and its retained embedding/projection parameters |
| Frozen components | VAE, DiT prefix, full reward teacher, aesthetic scoring MLP |
| Module mode | Evaluation mode during optimization; gradients still enabled for trainables |
| VAE latent | Posterior mode, FP32 encoding, same shift/scaling convention |
| Noise | `zσ = (1−σ)z + σε`, with σ drawn from Beta(2,2) on [0, 1] |
| Conditioning | Empty prompt; FLUX guidance embedding scalar 3.5 |
| Optimizer | AdamW; β₁ = 0.9, β₂ = 0.999, ε = 1e-8; weight decay 0 |
| Adapter learning-rate multiplier | 1; adapter and reward suffix use the same base LR |
| LR schedule | 100 optimizer updates of linear warmup, then constant |
| Gradient clipping | Global norm 1.0 over trainables, once per synchronized update |
| Non-finite values | Loss/gradient checks across ranks; abort before the corresponding update |
| EMA | Constant decay 0.999 from the first optimizer update; trainables only |
| Execution | BF16 autocast; `--optimize_speed`: TF32, cuDNN benchmark, fused AdamW |
| Seeds | Model/data 23456; bucket stream 23, reseeded each epoch |
| Checkpoints | Raw and EMA inference weights at every epoch end |

The loss combines token distillation and normalized image-embedding
distillation, with weight 1 for each. Aesthetic also compares frozen-MLP scores
with weight 0.1. Token tensors include both class and patch tokens. MSE or L1
applies to all supervised terms as specified in the pair table. The aesthetic
MLP stays deterministic and frozen while passing gradients to the student
embedding.

At the split, the suffix prepends a trainable class token and adds trainable
positional embeddings to the fitted patch features. These start from the
pretrained encoder's input embeddings; the teacher's evolved class token at
the split is not transferred. Search MSE measures patch features before this
step, so it is not the full student's initial distillation error.

location is `enc_blocks_N_dit_M`. A local search fits all candidate pairs,
including these defaults; adopting a different pair requires updating both the
location and file path in the launcher.

## Batch size and memory

`NPROC` is the total number of processes across all machines, normally one per
GPU. The launcher derives gradient accumulation:

```text
global batch = NPROC × MICRO_BATCH_SIZE × gradient_accumulation_steps
```

The quotient must be a positive integer. Lower `MICRO_BATCH_SIZE` to fit memory
while preserving the default global batch. `GLOBAL_BATCH_SIZE` overrides that
target; leave it unset to use the table above. If supplied, `GA` must equal the
derived accumulation. Changing the global batch changes optimizer/EMA updates
per epoch and the number of images seen during the fixed warmup.

| Example | Processes | Micro-batch/device | Accumulation | Global batch |
|---|---:|---:|---:|---:|
| SD3.5 CLIP defaults on one GPU | 1 | 16 | 16 | 256 |
| SD3.5 CLIP with a smaller micro-batch | 4 | 2 | 32 | 256 |
| FLUX or DFN defaults on four GPUs | 4 | 8 | 4 | 128 |

Distributed ranks use the same bucket for each synchronized micro-batch; an
accumulated update can combine buckets. Changing process count or micro-batch
preserves nominal image count, not the exact random or floating-point
trajectory. The final update in an epoch can contain fewer micro-batches;
Accelerate still scales losses by the configured accumulation. The trainer uses
the same initial model/data seed on every rank, without rank-specific reseeding
of the noise stream, so independent noise streams are not guaranteed.

Each process loads its own models. `STITCHVM_VAE_SLICING=1` reduces VAE batch
memory. For multiple machines, set `NNODES`, distinct `NODE_RANK` values in
`[0, NNODES)`, and a reachable coordinator `MAIN_IP`/`MAIN_PORT` on each machine.
Total `NPROC` must be divisible by `NNODES`. These settings configure launch;
they do not request scheduler resources.

## Checkpoints and logging

The launcher writes each model to `$OUT/stitchvm_<head>_<tag>/`, where `<head>` is
`hpsv2`, `clip`, `aesthetic`, or `dfn_clip`, and `<tag>` is `sd3`, `sd3_large`,
or `flux`. Each epoch exports raw and EMA inference weights; after five epochs:

```text
$OUT/stitchvm_<head>_<tag>/checkpoints/epoch_0005/
├── model_trainables.pt
└── model_trainables_ema.pt
```

The default downstream choice is the fifth-epoch EMA export. Both files contain
`stitching_layer`, `stitched_3d_model` (the reward-encoder suffix), and
`stitching_layer_location`. The aesthetic suffix also includes its frozen MLP.
Rebuild the same backbone, reward head, and stored location, then load both
module state dictionaries strictly. Check the location explicitly: tensor
shape compatibility alone cannot detect a wrong DiT depth when widths match.

Frozen VAE/DiT weights are loaded from their original pretrained sources.
Optimizer, scheduler, and random-generator states are not exported, so these
files cannot resume training exactly.

Terminal metrics print every 50 optimizer updates by default. `LOG_DIR` also
writes one JSONL row per synchronized update to
`$LOG_DIR/<model-output-basename>.jsonl`. Files are appended to; use a distinct
log directory for each run. `opt_step` resets each epoch, so identify rows by
epoch and step together. Losses describe the final micro-batch on the main
rank, not an average across all accumulated images and ranks. Optional Wandb
logging is off by default; install `wandb` separately to enable `--wandb_logging`.
Keep generated outputs and local run records outside version control.

For the twelve pairs, a standalone checkpoint-loading or intrinsic-evaluation
entry point is not included in this release (the two extensions include their
own; see their guides). Training losses are not intrinsic benchmark scores;
see the [results below](#results) for the reported intrinsic evaluation.

## Checks for a local run

- Preview the resolved command and compare its learning rate, global batch,
  micro-batch, and accumulation with the configuration above.
- Match the initialization file to the stored stitching location.
- Confirm both datasets load and input shapes follow the configured buckets.
- Confirm finite losses/gradients and the intended frozen/trainable components.
- Load raw and EMA exports into the matching architecture before downstream use.
